# 기자재 코드 자동 부여 및 반납 점검 통합 설계

## 상태

- 설계 승인일: 2026-07-29
- 대상 서비스: 광주대학교 사진영상미디어학과 예약 서비스
- 결정 사항: QR 코드는 사용하지 않고, 기존 기자재 전체의 코드를 재발급한다.

## 목표

관리자가 기자재 코드나 제품 정보를 검색해 대여·반납 업무를 처리할 수 있게 한다. 기존 기자재와 신규 기자재에는 사람이 읽을 수 있는 일관된 코드를 자동으로 부여하고, 반납 시 점검 결과에 따라 장비 상태를 자동 변경한다.

핵심 목표는 다음과 같다.

- 기존 기자재의 중복 코드와 `ITEM` 임시 코드를 제거한다.
- 신규 기자재 등록 시 관리자가 코드를 직접 만들지 않아도 된다.
- 코드, 이전 코드, 브랜드, 제품명, 모델, 기능, 분류, 보관 장소로 장비를 검색할 수 있다.
- 반납 처리와 장비 점검을 한 화면에서 완료한다.
- 기존 예약 및 대여 기록의 장비 연결을 보존한다.

## 범위

### 포함

- 기존 기자재 전체 코드 재발급
- 신규 기자재 자동 코드 생성
- 장비명에서 브랜드·모델·기능 정보 추출 및 표준화
- 코드 재발급 비교표와 경고 표시
- 관리자 기자재 통합 검색
- 관리자 대여·반납 장비 검색 및 선택
- 반납 결과에 따른 장비 상태 자동 전환
- 이전 코드 검색 지원 및 코드 변경 이력
- 단건 등록과 CSV 일괄 등록의 동일한 코드 생성 규칙

### 제외

- QR 코드 생성 및 실물 라벨 부착
- 학교 자산관리 번호 대체
- 구매·감가상각·폐기 결재 기능
- 수리업체 발주와 비용 정산
- 학생이 장비 상태를 직접 변경하는 기능

## 코드 체계

### 형식

```text
[분류]-[브랜드]-[제품키]-[일련번호]
```

예시는 다음과 같다.

| 장비 | 새 코드 |
|---|---|
| 소니 A7M3 | `CAM-SNY-A7M3-001` |
| 캐논 EF-S 18-55 | `LEN-CAN-EFS1855-001` |
| 삼양 AF 35mm F2.8 | `LEN-SAM-AF35F28-001` |
| Aputure 600X 조명 | `LGT-APT-600X-001` |
| DJI 매빅2 프로 | `DRN-DJI-MAVIC2PRO-001` |
| Rode 샷건 마이크 | `AUD-ROD-SHOTGUN-001` |
| 브랜드 미확인 삼각대 | `ETC-GEN-TRIPOD-001` |

### 분류 코드

| 분류 | 코드 |
|---|---|
| 카메라 바디 | `CAM` |
| 렌즈 | `LEN` |
| 조명 | `LGT` |
| 오디오 | `AUD` |
| 드론 | `DRN` |
| 기타 | `ETC` |

### 브랜드 코드

브랜드 코드는 명칭 변형과 한글 표기를 하나의 값으로 정규화한다.

| 입력 예시 | 코드 |
|---|---|
| Sony, SONY, 소니 | `SNY` |
| Canon, 캐논 | `CAN` |
| Nikon, 니콘 | `NIK` |
| Samyang, 삼양 | `SAM` |
| Aputure | `APT` |
| Rode, RØDE, 로데 | `ROD` |
| Zoom | `ZOM` |
| Atomos, 아토모스 | `ATM` |
| Profoto, 프로포토 | `PFT` |
| DJI | `DJI` |
| 브랜드 미확인 | `GEN` |

브랜드 사전은 코드 생성 모듈 한 곳에서 관리하며 필요할 때 확장한다.

## 자동 코드 생성 알고리즘

### 1. 입력 정규화

- 앞뒤 공백과 연속 공백을 제거한다.
- 영문은 대문자로 변환한다.
- 코드에 사용할 수 없는 문자를 제거한다.
- 한글·영문 브랜드 별칭을 표준 브랜드 코드로 변환한다.
- `Body`, `Lens`, `조명`, `카메라`처럼 제품 식별에 불필요한 일반 단어를 제품키 후보에서 제외한다.

### 2. 분류 결정

관리자가 지정한 분류를 우선 사용한다. 분류가 없을 때만 이름·모델·기능 태그를 기준으로 추론한다.

```text
렌즈, MM, MACRO, GM             → LEN
마이크, 레코더, XLR             → AUD
조명, 라이트, LED, 플래시        → LGT
드론, 매빅, MAVIC, 스파크        → DRN
카메라, BODY, EOS               → CAM
나머지                          → ETC
```

자동 추론한 분류는 저장 전에 관리자에게 표시한다. 여러 분류가 동시에 일치하거나 확신할 수 없으면 `ETC`로 저장하지 않고 확인 경고를 표시한다.

### 3. 브랜드 결정

명시적으로 입력한 브랜드를 우선 사용한다. 브랜드가 비어 있으면 제품명 첫 부분과 전체 문장에서 브랜드 사전을 검색한다. 찾지 못하면 `GEN`을 사용하고 관리자에게 브랜드 미확인 경고를 표시한다.

### 4. 제품키 생성

모델명이 있으면 모델명을 최우선으로 사용한다. 모델명이 없으면 제품명과 기능 태그에서 식별력이 높은 단어를 선택한다.

동일 제품의 표기 변형은 별칭 사전으로 통일한다.

```text
A7MIII, A7 MARK 3, A7M3       → A7M3
24-70MM F2.8                  → 2470F28
MAVIC 2 PRO, 매빅2 프로       → MAVIC2PRO
카메라 고정용 360도 어댑터     → 360CAMADPT
삼각대 고정용 360도 어댑터     → 360TRIPODADPT
```

제품키는 영문 대문자와 숫자로 제한하고 최대 16자로 만든다. 잘라낸 결과가 다른 제품과 충돌하면 다음 식별 단어를 추가한다. 그래도 충돌하면 저장을 중단하고 관리자가 모델 또는 기능 정보를 보완하게 한다.

### 5. 장비군 결정

다음 세 값이 같으면 동일 장비군으로 본다.

```text
분류 코드 + 브랜드 코드 + 제품키
```

보관 장소는 이동할 수 있으므로 코드에 넣지 않는다. 극기관과 판타지랩에 같은 제품이 있더라도 하나의 장비군에서 일련번호를 전역으로 부여한다.

### 6. 일련번호 부여

- 동일 장비군의 사용 이력을 포함한 최대 일련번호 다음 값을 사용한다.
- 세 자리 숫자를 기본으로 사용한다.
- 삭제·비활성·폐기된 장비의 번호는 재사용하지 않는다.
- 여러 관리자가 동시에 등록해도 서버가 하나의 트랜잭션에서 번호를 확정한다.

수량 3개를 등록하면 다음과 같이 연속 번호를 생성한다.

```text
CAM-SNY-A7M3-004
CAM-SNY-A7M3-005
CAM-SNY-A7M3-006
```

### 7. 코드 고정

한 번 부여한 코드는 장비명, 상태, 기능 태그 또는 보관 장소가 바뀌어도 유지한다. 잘못된 브랜드나 모델로 생성된 경우에만 관리자가 명시적으로 `코드 재생성`을 실행할 수 있다. 재생성 전 코드는 이전 코드 목록과 감사 로그에 보존한다.

## 기존 기자재 전체 재발급

### 재발급 순서

1. 현재 기자재와 기존 코드를 백업한다.
2. 장비명·브랜드·모델·비고에서 표준 필드를 추출한다.
3. 명칭 별칭 사전을 적용한다.
4. 내부 `equipment.id`를 기준으로 안정적인 정렬을 수행한다.
5. 장비군별로 `001`부터 일련번호를 부여한다.
6. 새 코드의 전체 중복 여부를 검사한다.
7. 기존 코드와 새 코드의 비교표 및 경고를 관리자에게 표시한다.
8. 전체 적용 요청에서 코드, 이전 코드, 코드 버전, 변경 이력을 하나의 트랜잭션으로 저장한다.

### 경고 대상

- 기존 코드가 다른 장비와 중복된 경우
- 브랜드를 찾지 못한 경우
- 모델 또는 제품키를 구분할 수 없는 경우
- 동일 제품으로 보이지만 기능 설명이 충돌하는 경우
- 현재 예약이 연결된 장비인데 내부 ID가 누락된 경우

경고 없는 항목과 관리자가 확인한 항목만 적용할 수 있다. 적용 도중 하나라도 저장에 실패하면 전체 변경을 취소한다.

### 예약 데이터 보존

예약과 대여 기록은 표시 코드가 아니라 기존 `equipment.id`를 계속 참조한다. 코드 변경으로 예약 연결이 바뀌지 않아야 한다. 예약에 과거 코드 문자열이 복사되어 있는 경우 표시 시 현재 장비 코드를 우선 사용하고 과거 값은 감사 자료로만 남긴다.

## 신규 장비 등록

관리자 등록 폼은 다음 필드를 사용한다.

- 분류
- 브랜드
- 제품명
- 모델
- 기능 태그
- 보관 장소
- 수량
- 상태
- 예약 가능 여부
- 비고

현재의 수동 `codePrefix` 입력은 기본 화면에서 제거한다. 필수 정보를 입력하면 예상 코드를 실시간으로 표시하고, 저장 시 서버가 실제 코드와 일련번호를 다시 계산한다.

단건 등록과 CSV 등록은 동일한 코드 생성 함수를 사용한다. CSV에 코드가 포함되어 있더라도 일반 가져오기에서는 참고값 또는 이전 코드로만 저장하고, 새 코드는 서버 규칙에 따라 생성한다.

## 통합 장비 검색

관리자 장비 선택 검색은 다음 필드를 하나의 검색 색인으로 합친다.

- 현재 코드
- 이전 코드
- 브랜드
- 제품명
- 모델
- 기능 태그
- 분류
- 보관 장소
- 비고

검색 결과에는 코드, 제품명, 브랜드·모델, 보관 장소, 현재 상태, 예약 가능 여부를 표시한다. 대여 중인 장비는 현재 대여자, 연락처, 예약 기간도 함께 표시한다.

정확한 코드 일치는 가장 위에 표시하고, 그 다음 제품명·모델 일치, 브랜드·기능 일치 순으로 정렬한다.

## 반납 점검 통합

### 관리자 처리 흐름

1. 예약 목록이나 장비 검색에서 대여 중인 장비를 선택한다.
2. 현재 대여자, 연락처, 예약 기간과 선택된 장비를 확인한다.
3. 각 장비의 반납 결과를 선택한다.
4. 필요한 경우 메모를 입력한다.
5. 서버가 예약 상태와 장비 상태를 함께 변경한다.

### 반납 결과

| 선택 | 예약 상태 | 장비 상태 | 학생 예약 노출 |
|---|---|---|---|
| 정상 | `returned` | `가능` | 노출 |
| 점검 필요 | `returned` | `수리중` | 제외 |
| 파손·수리 필요 | `returned` | `수리중` | 제외 |

파손·수리 필요는 사유 입력을 필수로 한다. 현재 서비스 상태 체계와 호환하기 위해 운영 상태는 `수리중`을 사용하고, 점검 결과의 세부 유형은 별도 검사 기록에 저장한다. 관리자가 최종적으로 복구 불가라고 판단하면 기존 장비 관리 화면에서 `파손`으로 변경할 수 있다.

여러 장비를 한 예약에서 반납할 때 장비마다 다른 결과를 선택할 수 있다. 모든 장비 처리와 예약 상태 변경은 하나의 요청으로 수행한다.

## 화면 설계

### 기자재 관리 화면

- 상단: `장비 추가`, `장비 관리`, `코드 재발급` 탭
- 장비 추가: 자동 코드 미리보기와 추론 경고
- 장비 관리: 통합 검색, 현재 코드와 이전 코드 표시
- 코드 재발급: 기존/신규 코드 비교표, 경고 필터, 전체 적용 버튼

전체 재발급이 완료되면 `코드 재발급` 탭은 완료 이력과 결과 다운로드 화면으로 바뀐다. 반복 실행은 별도 재생성 권한과 확인 절차가 있어야 한다.

### 예약 관리 화면

- `대여 처리`와 `반납 처리`에서 장비 검색·선택 사용
- 반납 처리 바텀시트 또는 모달에 장비별 상태 선택 제공
- 모바일에서도 코드, 장비명, 점검 상태와 메모 입력이 한 화면에 표시
- 성공 후 예약 목록, 관리자 대시보드 큐, 장비 목록을 새로 불러옴

## 데이터 모델

### 기자재 필드

```text
equipment.code                현재 코드, 전체에서 고유
equipment.legacyCodes         이전 코드 배열
equipment.brand               표준 브랜드명
equipment.brandCode           표준 브랜드 코드
equipment.model               관리자 표시용 모델명
equipment.productKey          코드 생성용 정규화 제품키
equipment.functionTags        기능 검색 태그 배열
equipment.codeVersion         신규 체계는 2
equipment.codeAssignedAt      마지막 코드 부여 시각
equipment.codeAssignedBy      작업 관리자 ID 또는 migration
```

기존 `id`, `source`, `facility`, `category`, `name`, `status`, `reservable`, `inquiryOnly`, `active` 필드는 유지한다.

### 반납 검사 기록

```text
equipmentInspection.id
equipmentInspection.equipmentId
equipmentInspection.reservationId
equipmentInspection.outcome       normal | needs_inspection | needs_repair
equipmentInspection.note
equipmentInspection.previousStatus
equipmentInspection.nextStatus
equipmentInspection.checkedBy
equipmentInspection.checkedAt
```

검사 기록은 수정하지 않고 후속 상태 변경을 별도 감사 로그로 남긴다.

### 코드 재발급 작업

```text
equipmentCodeMigration.id
equipmentCodeMigration.status     preview | applied | failed
equipmentCodeMigration.codeVersion
equipmentCodeMigration.items      equipmentId, oldCode, newCode, warnings
equipmentCodeMigration.createdBy
equipmentCodeMigration.createdAt
equipmentCodeMigration.appliedAt
```

```text
GET  /api/admin/equipment/code-migrations/:id
GET  /api/admin/equipment/search?q=
POST /api/admin/equipment
POST /api/admin/equipment/import
POST /api/admin/reservations/:id/return-inspection
```

- 미리보기는 데이터 변경 없이 매핑과 경고만 반환한다.
- 적용 API는 같은 작업을 두 번 요청해도 중복 변경하지 않는 멱등성을 가져야 한다.
- 장비 등록 API 응답은 서버가 최종 확정한 코드를 반환한다.
- 반납 검사 API는 장비별 결과 배열을 받고 예약 및 모든 장비 상태를 트랜잭션으로 변경한다.

## 오류 및 동시성 처리

- 생성된 코드가 이미 존재하면 최신 최대 번호를 다시 읽고 재시도한다.
- 정보가 부족해 안전한 제품키를 만들 수 없으면 `400`과 보완할 필드를 반환한다.
- 이미 적용된 마이그레이션을 다시 적용하면 기존 결과를 반환하고 새 변경은 만들지 않는다.
- 마이그레이션 미리보기 이후 장비 데이터가 변경되면 적용을 거부하고 새 미리보기를 요구한다.
- 대여 중이 아닌 예약에는 반납 검사를 실행할 수 없다.
- 예약에 포함되지 않은 장비의 검사 결과가 들어오면 전체 요청을 거부한다.
- 파손·수리 필요 결과에 사유가 없으면 저장하지 않는다.
- 반납 처리 중 일부 장비만 변경되는 부분 성공을 허용하지 않는다.

## 권한과 감사

- 코드 재발급, 코드 재생성, 반납 점검은 관리자만 수행한다.
- 감사 로그에는 이전 값, 새 값, 관리자, 시각, 대상 장비와 예약 ID를 기록한다.
- 이전 코드는 학생 화면의 기본 정보로 노출하지 않고 관리자 검색과 이력에서만 사용한다.
- 연락처는 기존 관리자 예약 권한 안에서만 표시한다.

## 테스트

### 코드 생성 단위 테스트

- 한글·영문 브랜드 표기의 동일 코드 변환
- 모델 별칭 정규화
- 제품키 특수문자 제거와 최대 길이
- 서로 다른 제품의 충돌 감지
- 동일 장비군의 연속 번호 생성
- 삭제·비활성 번호 미재사용
- 수량 등록과 CSV 등록의 동일 규칙

### 마이그레이션 테스트

- 현재 144개 데이터에서 새 코드 중복 0건
- 현재 중복 코드들이 서로 다른 새 코드로 변환됨
- 모든 `ITEM` 임시 코드가 제품 기반 코드로 변환되거나 경고됨
- `equipment.id`와 예약 연결 유지
- 미리보기 무변경 보장
- 전체 적용의 트랜잭션 롤백과 재요청 멱등성

### 반납 처리 테스트

- 정상 반납 시 예약과 장비 상태 전환
- 점검 필요 및 수리 필요 장비의 예약 대상 제외
- 여러 장비의 서로 다른 결과 처리
- 사유 필수 검증
- 허용되지 않은 예약 상태와 장비 ID 거부
- 감사 로그 및 검사 이력 생성

### 화면 테스트

- 코드·이전 코드·브랜드·모델·기능 검색
- 정확한 코드 우선 정렬
- 자동 코드 미리보기와 경고
- 모바일 반납 점검 입력
- 처리 성공 후 예약·장비·대시보드 갱신

## 배포 및 적용 순서

1. 코드 생성기와 데이터 필드를 배포한다.
2. 신규 등록 및 검색 기능을 배포한다.
3. 운영 데이터 백업을 생성한다.
4. 프로덕션 데이터로 코드 재발급 미리보기를 생성한다.
5. 경고 항목을 확인하고 전체 재발급을 적용한다.
6. 이전 코드와 새 코드 비교 결과를 보관한다.
7. 반납 점검 통합 화면을 활성화한다.
8. 전체 관리자·학생 예약 회귀 테스트를 수행한다.

## 완료 기준

- 활성·비활성 기자재를 포함한 모든 기존 장비에 중복 없는 신규 코드가 부여된다.
- 신규 장비는 수동 코드 입력 없이 자동 코드를 받는다.
- 현재 코드와 이전 코드로 같은 장비를 찾을 수 있다.
- 브랜드, 제품명, 모델, 기능, 분류, 보관 장소 검색이 동작한다.
- 반납 결과에 따라 예약과 장비 상태가 일관되게 변경된다.
- 수리중 장비는 학생 예약 후보에서 제외된다.
- 기존 예약 기록과 장비 연결이 유지된다.
- 변경 및 점검 이력이 관리자 감사 로그에 남는다.
