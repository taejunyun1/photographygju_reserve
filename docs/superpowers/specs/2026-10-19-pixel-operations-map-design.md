# 픽셀아트 운영 지도 설계안

작성일: 2026-10-19

## 후속 확정 사항

같은 날 사용자 제공 평면 스케치와 목업 검토를 거쳐 **긴 복도의 평면 픽셀 배치**로 확정했다. 예약 대상인 스튜디오 A/B·암실·출력실과 기자재실만 정보/상호작용을 구현하고, 다른 공간은 회색 윤곽으로 남긴다. 최신 목업은 `../../../outputs/pixel-operations-map-20261019/flat-timeline-mockup.html`이다.

현재 제품의 디자인/색상에 맞춰 **관리자 대시보드 메인과 예약자 홈 대시보드 메인**에 공통 현황판을 넣기로 했다. 학과 홈페이지 연동은 후속 단계로 유지한다. 구현 범위·스타일·인증된 데이터 경로·예약 연결은 [최신 구현 계획](../plans/2026-10-19-pixel-facility-dashboard.md)이 이 초기 설계안보다 우선한다. 아래 초기 컨셉/API 제안은 검토 기록으로 보존한다.

## 현재 상태

사용자가 선택한 방향은 **학과 공간을 축소한 미니어처 지도**다. 스튜디오·암실·기자재실을 한 장면에 표현하고 학과 홈페이지와 예약 관리자 화면에 함께 사용한다.

- 이미지 시안: `../../../outputs/pixel-operations-map-20261019/concept.png`
- 이미지는 개념도이며 실제 건물 배치와 다를 수 있다. 화면 속 수량·상태는 예시다.
- 이 문서는 구현 설계안이다. 픽셀 지도 기능, 공개 API, 홈페이지 연동은 아직 구현하거나 배포하지 않았다.
- 앞서 요청한 운영 인사이트 압축 UI는 별도로 구현·검증·운영 배포를 완료했다.

## 사용자에게 제공할 정보

한눈에 현재 예약된 공간과 대여 중인 장비 규모를 파악하고, 필요한 항목을 누르면 짧은 상세 정보나 기존 예약 화면으로 이동한다. 기존 운영 인사이트는 최근 추세를, 지도는 현재 시점의 상태를 담당한다.

| 화면 | 기본 표시 | 누른 뒤 표시/동작 |
| --- | --- | --- |
| 학과 홈페이지 | 공간별 현재 예약 상태, 카메라·렌즈·조명 등 분류별 대여 수량, 갱신 시각 | 해당 공간/분류의 간단한 설명과 예약 사이트 링크 |
| 예약 관리자 | 같은 지도와 공개 집계 정보 | 권한을 확인한 기존 데이터로 장비명·개별 코드·반납 예정 정보를 간단히 표시하고 관리 목록으로 이동 |

공개 화면에는 대여자 이름, 학번, 연락처, 목적, 메모, 참가자 수, 예약 ID, 개별 장비 코드, 예약별 시간표를 보내지 않는다. 관리자 정보는 기존 인증 경로에서만 가져온다.

## 화면 구성

1. 제목: `지금, 사진영상미디어학과`
2. 미니어처 장면: 스튜디오 A/B, 암실, 출력실, 기자재실. 공간 배치는 개념도이며 실제 설정에 맞춰 표시한다.
3. 공간에 예약이 있으면 조명과 작은 상태 표지를 바꾼다. 모든 상태에는 읽을 수 있는 텍스트를 함께 둔다.
4. 기자재실에는 카메라·렌즈·조명 선반을 배치한다. 빈 슬롯은 대여 상태를 상징하며 실제 장비 위치나 실제 선반 배치를 의미하지 않는다. 정확한 수량은 텍스트로 표시한다.
5. 아래에는 분류별 대여 수량을 한 줄로 표시한다. 운영 데이터가 없는 분류를 임의로 만들어 표시하지 않는다.
6. 홈페이지에 `예약하러 가기`, 관리자에 기존 관리 목록으로 이어지는 동작을 제공한다.

픽셀 표현은 공간과 장비 그림에 집중하고, 제목·상태·수량은 선명한 일반 글꼴로 쓴다. 사람 캐릭터나 실시간 위치 표시를 넣지 않는다. 자동 움직임은 초기 범위에서 제외한다.

모바일은 지도 아래에 짧은 상태 목록을 제공한다. 그림 속 작은 글자를 읽거나 정밀하게 눌러야만 정보를 얻는 구조를 피한다. 클릭 상세는 여러 큰 카드를 반복하지 않고 선택된 항목의 2~3줄 요약 하나만 보여준다.

## 데이터 의미

### 공간

- 표시 문구: `현재 예약 시간`, `현재 예약 없음`, `확인 불가`.
- 현재 예약이 없다는 이유만으로 실제 공실이나 즉시 이용 가능 상태라고 단정하지 않는다.
- 서버의 현재 시각과 확정된 유효 예약의 개별 시간 구간을 비교한다. 현행 공간 예약의 확정 상태인 `auto_confirmed`를 포함하고, `completed`·대기·취소·반려는 현재 예약으로 집계하지 않는다. 장비 승인 상태인 `approved`만 조회하는 방식을 공간에 적용하지 않는다.
- 스튜디오의 수량 단위는 앞·뒤 구획이다. 암실 정원은 인원, 출력실 정원은 시간 구간별 예약 건수로 서로 다르므로 초기 공개 화면에서는 두 공간의 상태만 표시하고 수량은 `null`로 둔다. 참가자 수를 공개하지 않는다.
- 떨어진 슬롯 사이의 공백과 자정을 넘는 슬롯을 각각 처리한다. 첫 시작부터 마지막 종료까지의 넓은 범위를 통째로 예약 중으로 판정하지 않는다.
- 초기 지도는 현재 예약 상태를 표시한다. 점검·예약 제한의 별도 집계는 초기 범위에서 제외하며, 예약 가능 여부의 최종 판단은 기존 예약 화면이 담당한다. 지도에서 `예약 없음`을 `이용 가능`으로 바꾸지 않는다.

### 장비

- `checked_out` 예약에 포함된 고유 장비 ID를 집계한다. 예약 건수가 아니라 실제 항목 수다.
- 승인되었지만 아직 반출 처리되지 않은 예약은 대여 중에 포함하지 않는다.
- 예정 반납일이 지나도 반납 처리 전까지 대여 중으로 유지한다. 오늘 예약만 조회하면 이전 날짜에 반출된 장비가 누락되므로 전체 미반납 상태를 조회한다.
- 기존 `equipmentCheckedOut`은 예약 건수이므로 항목 수로 재사용하지 않는다. `occupiedEquipment`도 예약 점유와 실제 반출이 섞여 있어 대여 수량으로 재사용하지 않는다.
- 장비의 현재 물리적 위치는 저장되지 않으므로 특정 스튜디오에 장비가 있다고 표현하지 않는다.

## 공유 구현과 연동 구조

```text
예약 서버의 원본 예약/장비 데이터
  → 공개 필드만 집계하는 순수 함수
  → GET /api/public/facility-status
      → 예약 관리자: 공통 지도 + 기존 인증된 상세 경로
      → 학과 홈페이지의 /api/reservation-status 프록시
          → 공통 지도 + 예약 링크
```

API 경로는 제안이며 기존 라우트와 충돌 여부를 구현 시 확인한다.

### 공개 계약

```ts
type FacilitySceneStatus = {
  schemaVersion: 1;
  sceneVersion: string;
  generatedAt: string;
  validUntil: string;
  timeZone: "Asia/Seoul";
  spaces: Array<{
    key: string; // 사전에 허용한 공간 키만 사용
    label: string; // 공개 공간명
    reservationState: "reserved_now" | "no_current_reservation" | "unknown";
    reservedUnitCount: number | null; // 스튜디오의 현재 예약 구획 수, 암실/출력실은 null
    totalUnitCount: number | null; // 스튜디오 전체 구획 수, 암실/출력실은 null
  }>;
  equipment: {
    checkedOutItemCount: number | null;
    categories: Array<{
      key: string;
      label: string;
      checkedOutItemCount: number | null;
    }>;
  };
};
```

기존 `publicReservationSummary`에는 사용자 이름·ID와 예약 ID가 있으므로 공개 API에 재사용하지 않는다. 새 응답은 허용된 필드만 명시적으로 구성하고 원본 예약 객체를 펼쳐 넣지 않는다.

프레임워크에 의존하지 않는 SVG 픽셀 장면과 스타일, 상태 계약을 공유한다. 예약 프로젝트에서 원본을 관리하고 홈페이지에는 같은 버전의 장면을 빌드 시 반영한다. 생성 이미지는 미술 방향의 참고 자료이며, 이미지 안에 쓰인 숫자를 운영 UI로 사용하지 않는다. 실제 상태·숫자는 HTML로 갱신한다.

홈페이지 프록시는 고정된 예약 서버의 공개 GET 경로만 요청한다. 방문자의 Cookie/Authorization을 전달하지 않고, 응답도 허용 목록으로 검증·재구성한다. 기존 홈페이지와 같은 출처에서 데이터를 받아 외부 iframe이나 CSP 확장을 추가할 필요가 없다.

### 배치와 파일 경계

- 예약 관리자: `src/react/admin/screens/AdminDashboard.tsx`에 현재 상태 요약으로 배치한다. 기존 압축 인사이트와 관리 동작을 보존한다.
- 학과 홈페이지: 새 `src/components/ReservationOverview.astro`와 `functions/api/reservation-status.js`를 추가하는 방식이 적합하다.
- 홈페이지 첫 화면은 기존 학과 지표 다음, 시설 페이지는 예약 안내 다음에 삽입한다. 새 고정 플로팅 UI를 만들지 않는다.
- 홈페이지 저장소에는 진행 중인 수정이 많으므로 변경 전 상태를 확인하고 위 삽입점 밖의 기존 작업을 수정하거나 되돌리지 않는다.

## 갱신과 오류

- 첫 진입 시 불러오고 화면이 보일 때 60초 간격으로 갱신한다. 페이지 복귀 시 다시 확인한다.
- 마지막 서버 갱신 시각을 표시한다. 실시간 센서 기반 상태라고 표현하지 않는다.
- 실패·만료·계약 불일치는 `확인 불가`로 표시한다. 빈 응답을 0건이나 예약 없음으로 변환하지 않는다.
- 마지막 정상 응답을 잠시 보존할 경우 오래된 정보임을 표시하고 유효기간 이후에는 현재 상태로 사용하지 않는다.
- 키보드와 화면 읽기 프로그램으로도 같은 정보를 이용할 수 있어야 한다. 색상 외에 텍스트·모양으로 상태를 구분한다.

## 구현 후 확인할 항목

- 공개 응답에 사용자/예약 개인정보가 없고 로그인 여부와 무관하게 동일한 공개 필드만 반환되는지.
- 비연속 슬롯, 자정 경계, 취소·반려, 실제 반납, 이전 날짜 반출, 반납 기한 경과, 중복 장비 ID를 정확히 처리하는지.
- 공개 프록시가 고정 목적지만 사용하며 인증 헤더를 전달하지 않는지.
- 장애·만료 시 예약 없음/0건으로 잘못 보이지 않는지.
- 390px 모바일과 데스크톱에서 수량·상태·클릭 대상이 읽히고 조작되는지.
- 홈페이지와 관리자 지도 버전 및 상태 의미가 일치하는지.
- 운영 배포 후 두 사이트의 API·화면·자산을 각각 확인했는지. 로컬 시안이나 빌드 성공을 실데이터 연동 완료로 보고하지 않는다.
