# 디지털사진영상실 좌석 예약 설계안

작성일: 2026-11-09
상태: 사용자 승인 후 구현 중. 최종 시간 정책은 2시간 단위·24시간 운영·당일 예약이다.
기준 코드: 78abedd44e1b8680e9d9bdf98372a2dfc89d7a2c

## 사용자 확정 요구

- 시설명은 디지털사진영상실이다.
- Mac 12석, PC 4석을 개별 좌석으로 예약한다.
- 스튜디오·암실·출력실과 같은 예약 시스템 안에서 관리한다.
- 수업 때문에 예약할 수 없는 시간대를 관리자가 등록할 수 있어야 한다.
- 예약은 2시간 단위이며 당일 예약을 허용한다.

## 접근 방식

기존 예약에 digital_lab 유형을 추가한다. 기존 로그인·승인 상태·예약 생성/수정/취소·내 예약·관리자 예약·알림 흐름을 재사용하고, 좌석과 시간의 겹침 판정만 별도 도메인 모듈로 분리한다.

기존 스튜디오의 공간 이름에 16석을 넣는 방법은 스튜디오 전날 마감·시간표·보고서 정책까지 섞이므로 채택하지 않는다. 독립 좌석 예약 서비스를 만드는 방법은 계정·운영 화면·예약 내역을 이중으로 관리하게 되므로 채택하지 않는다. 사용자의 “스튜디오 등과 동일하게 취급” 요청에 맞춰 기존 서비스의 시설 유형 확장을 제안한다.

## 제안 기본값

다음 기본값은 사용자의 계획 구현 승인에 따라 적용하며, 이후 확정한 2시간 단위와 24시간 운영 조건을 우선한다.

- 좌석 ID는 mac-01~mac-12, pc-01~pc-04로 고정한다. 표시명은 Mac 01~Mac 12, PC 01~PC 04로 한다.
- 승인된 사용자는 예약과 동시에 자동 확정된다.
- 한 예약에 한 좌석만 선택한다. 한 사용자는 디지털사진영상실의 같은 시간에 두 좌석을 예약할 수 없다.
- 여러 시간은 연속된 2시간 구간으로 선택한다. 별도 일일 시간 제한은 우선 추가하지 않는다.
- 시간은 00:00, 02:00, 04:00처럼 짝수 정각 기준이다. 오늘 11:30에는 12:00 이후부터 예약할 수 있으며 이미 시작한 구간은 선택할 수 없다.
- 시간 비교는 Asia/Seoul 기준이며 시작을 포함하고 종료를 제외한다. 10:00~12:00과 12:00~14:00은 연이어 예약할 수 있다.
- 한 예약이 자정을 넘지 않는다. 종료 시각 24:00은 당일의 끝으로 처리한다.
- 예약 가능 기간은 기존 reservationWindowDays 설정을 따른다.
- 운영 시작·종료 시간은 관리자 설정으로 둔다. 사용자가 24시간 운영을 확정했다. 초기 digitalLabEnabled=false, 운영 시간은 빈 값으로 두고 유효한 시간 설정 후 활성화한다.
- 좌석 예약에는 스튜디오 사용 보고서·기자재 반출/반납 정책을 자동으로 적용하지 않는다.

## 예약자 화면

새 예약 → 디지털사진영상실 → 날짜 → 시작/종료 시간 → 좌석 → 확인 → 자동 확정.

좌석은 Mac 12석과 PC 4석으로 나눠 버튼 형태로 표시한다. 예약 가능, 다른 예약 있음, 내 예약, 수업으로 이용 불가, 선택 중 상태를 문자와 시각적 표시로 함께 구분한다. 시간 변경 시 좌석 가용 상태를 다시 조회한다. 선택 좌석을 조용히 다른 좌석으로 바꾸지 않는다.

확인 화면과 내 예약에는 시설명, 좌석 번호, 날짜, 이용 시간을 표시한다. 상세·수정·취소는 기존 흐름에 연결한다. 휴대전화 화면에서 모든 좌석을 가로 스크롤 없이 선택할 수 있어야 한다.

실제 강의실 배치 자료는 제공되지 않았다. 첫 버전은 기종별 좌석 목록이며 실제 책상 위치를 추측한 도면을 만들지 않는다.

## 수업 차단

관리자 설정의 기존 “수업/학기 차단 일정” 시설 선택에 디지털사진영상실을 추가한다.

입력값은 시설, 요일, 적용 시작일/종료일, 시작/종료 시간, 수업명이다. 학기 동안의 주간 반복을 지원하고, 하루만 차단할 때는 시작일과 종료일을 같게 한다. 첫 버전의 수업 차단 범위는 16석 전체다.

차단 시간은 분 단위까지 정확히 판정한다. 예를 들어 10:30~12:10 수업이면 10:00~12:00, 12:00~14:00을 모두 선택할 수 없다. 디지털사진영상실의 차단 일정은 같은 날의 시작<종료로 제한한다.

새 차단 일정이 기존 유효 예약과 겹치면 저장을 거부하고 관리자에게 충돌 목록을 보여준다. 관리자가 기존 예약을 수정/취소한 뒤 다시 저장한다. 예약을 자동 삭제하거나 자동 취소하지 않는다. 다른 시설의 기존 차단 저장 동작은 변경하지 않는다.

## 서버와 데이터

예약 type은 digital_lab, fields는 reservedDate, seatId, startTime, endTime, purpose, phone이다. 좌석의 기종은 서버의 고정 좌석 목록에서 결정하며 클라이언트 입력을 신뢰하지 않는다.

reservations 테이블은 이미 type과 전체 JSON data를 저장하므로 신규 예약 테이블 없이 확장할 수 있다. 기존 행과 설정값을 보존하는 정규화·SQL 왕복 테스트를 실행한다.

가용 좌석 조회와 최종 저장은 동일한 도메인 판정 함수를 사용한다. 저장 시 현재 시각, 운영 시간, 계정 승인, 좌석 ID, 다른 예약, 본인의 중복 예약, 수업 차단을 다시 확인한다. 동시 요청에서 한 좌석을 둘이 확보할 수 없어야 한다.

학생 응답에는 타인의 이름·연락처·예약 ID를 싣지 않는다. 본인과 관리자에게는 기존 권한 범위의 상세 이동을 제공한다.

## 기존 화면 연결

- 내 예약 및 홈 예약 요약에 좌석과 이용 시간 표시.
- 관리자 예약 검색·필터·상세·수정·취소와 집계에 시설 유형 추가.
- 기존 공간·장비 현황에 디지털사진영상실 요약과 좌석 상세 추가.
- 요약은 선택 구간 전체에서 사용 가능한 Mac n/12, PC n/4를 표시.
- 기존 복도 지도에 강의실의 위치를 임의로 끼워 넣지 않고 별도 시설 요약으로 연결.
- 기존 예약 알림 형식에 시설·좌석·시간 포함. 테스트에서는 실제 외부 알림을 보내지 않음.

## 완료 기준

Mac 12석과 PC 4석이 정확히 표시되고 각각 예약할 수 있어야 한다. 같은 좌석의 겹침 예약과 같은 사용자의 동시간대 복수 좌석 예약을 서버에서 막아야 한다. 당일 미래 시간 예약, 시간 경계, 취소 후 재예약, 수업 반복 차단, 관리자 충돌 안내가 검증돼야 한다. 기존 네 가지 시설 예약과 기존 데이터에 회귀가 없어야 한다.

사용자가 이 계획의 구현·테스트·웹 배포를 승인했으며 진행 중이다. 이후 수정된 2시간 단위와 24시간 운영 조건을 적용한다.
