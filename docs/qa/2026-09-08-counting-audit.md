# 숫자 집계 정합성 점검

## 수정한 불일치

1. 예약·보고서·공지·특강 목록의 배지는 현재 페이지 행 수 대신 API의 필터 적용 총계를 표시한다. 현재 표시 행 수는 별도로 제공한다. 학생 목록의 0건은 거짓 값으로 처리해 이전 배열 길이로 대체하지 않는다.
2. 대시보드에서 예약 목록으로 이동할 때 이전 학기·기간·시간 필터를 초기화한 후 카드 조건을 적용한다.
3. 최근 취소율 클릭은 접수일 기준(`dateBasis=created`, 한국시간)으로 조회한다. 기본 목록은 예약일 기준이다. UI에서 기준을 표시한다.
4. 예약 많은 시간 클릭은 유효 상태만 조회한다. 시간은 부분 일치가 아니라 정확히 비교한다.
5. 오늘 취소 카드에 관리자 취소를 포함한다. 반납·취소 카드는 오늘 예약일 기준임을 표시한다.
6. 보고서 확인 큐는 보고서 목록과 같은 상태 판정(상위 status, fields.status, submittedAt 순)을 사용한다.
7. 일괄 작업의 대상 필터에도 현재 목록의 기간·시간·접수일 기준을 전달한다. 실제 데이터 삭제는 하지 않았다.
8. 수요조사 응답은 학생별 최신 한 건, 과목은 한 응답당 한 번 집계한다. 대상 수는 현재 대상 학생과 기존 응답자의 합집합으로 계산한다. 학년·승인 변경으로 과거 응답자가 분모에서 사라지는 문제를 막는다.

## 확인한 기존 기준

- 승인 대기 학생: 학생 역할 및 approval_pending. 페이지 크기와 무관한 서버 총계를 사용한다.
- 특강 신청 수: 내부 신청 레코드 + 관리자가 입력한 외부 기초 신청 수. 취소 시 신청 레코드를 제거한다.
- 장비 목록: 전체 장비를 받아 클라이언트에서 필터링하므로 필터 배열 길이가 해당 결과 전체 수다.
- 학생 최근/지난 예약: 전체 본인 예약을 날짜별로 분류한 배열의 수. 표시 제한과 전체 분류 수는 별도다.
- 운영 지표 기간 및 가용 장비 계산은 2026-09-08-operating-metrics.md를 따른다.

## 검증

`npm run test:dashboard-integrity`에 API 교차 검증을 포함했다. 105건/페이지 크기 7 및 2, 관리자 취소, 접수일과 예약일이 다른 요청, 보고서 레거시 상태, 동일 시간대의 취소 제외, 학생 승인, 특강 신청 기초 집계를 확인한다. 브라우저에서는 총 105건/현재 2건 표시, 카드 이동의 상태·기간 필터를 검증한다.

운영 데이터 자체를 수정하거나 삭제하지 않고 계산과 표시를 변경한다. 운영 계정의 개별 실데이터 전체를 수작업 대조한 감사는 아니며, 검증용 데이터로 API 및 UI 계약을 검증한다.
